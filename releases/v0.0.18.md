# RA2A v0.0.18

## Highlights

- **Codex CLI receipt confirmation:** Delivery acknowledges that the native host accepted the input, independently of model execution, business replies or turn completion. Uncertain writes remain `DELIVERY_UNKNOWN` and are never automatically replayed.
- **Correct CLI ownership and recovery:** Explicit CLI registration survives shared Desktop history enumeration. Direct delivery requires the host's explicit input capability; daemon probes respect the selected `CODEX_HOME`. Disconnected RPC clients recover for subsequent operations without replaying an uncertain write.
- **Preserve native Codex use:** The launcher keeps a healthy official daemon and validates RA2A fallback usability. Windows managed control directories enforce private current-user permissions without recursively changing the profile or taking ownership of unrelated resources. Installers prefer the self-updatable standalone Codex distribution.
- **OpenCode resume follows the actual TUI:** Each attached client tracks its own current native session through a temporary TUI plugin. Resume restores the original RA2A address; session switches withdraw the previous attachment. Home routes, plugin disposal and expired heartbeats withdraw endpoints. Per-session automatic permission replies follow the current attachment.

## Validation and support boundaries

- Release preparation passed Go 1.24 full tests, `go vet`, all 18 executable builds across six OS/architecture targets, and installation of actual Linux/amd64 assets through the unchanged Release downloader in an isolated profile. Binary version and generated checksums were verified.
- Codex CLI acceptance covered Linux, macOS and Windows, native Codex 0.159.3/0.160.0 where recorded, multi-round cross-device receipt and execution evidence, active input, isolated daemon recovery and uncertain network receipt without replay. The owner confirmed the CLI-to-CLI manual acceptance.
- Codex CLI-to-OpenCode testing covered 22 forward and 22 reverse messages, busy receipt and continued execution. The resume fix passed isolated real OpenCode 1.18.34 on Linux and 1.18.33 on Windows, including independent client navigation and attachment expiry. ROG's real restart/resume restored the original session address; the owner confirmed visible messages/replies and continued manual input.
- Codex CLI and OpenCode retain their **preview** status. These results do not claim all App/CLI/OpenCode platform pairs, physical network outage recovery or real OpenCode shared-server crash recovery. Platform-specific skips remain documented; native fixture navigation is distinct from human screen confirmation.
- Temporary TUI plugin injection preserves existing configuration and relative plugin paths. The directory containing an explicit `OPENCODE_TUI_CONFIG` override must permit creation of a temporary sibling file. Invalid or unreadable overrides fail visibly. OpenCode's own plugin loader may install dependencies in existing `.opencode` directories under its normal policy.
- App login/model/proxy repairs performed locally during diagnosis are not shipped as global network or authentication changes in this release.

## Upgrade

- Use the standard v0.0.18 Release installer to update RA2A and both launchers. Updating only the core binary does not provide the new OpenCode TUI tracking plugin; core and OpenCode wrapper must be upgraded together.
- Reopen an existing OpenCode TUI yourself, then use its normal resume/session picker. Already-running wrapper processes keep their old implementation. Do not infer the currently selected session from an attach process's startup `--session` argument.
- Keep official Codex/OpenCode binaries, login state and model/proxy settings. The resume fix does not require restarting the existing shared OpenCode server or changing MCP configuration when those settings are already correct.
