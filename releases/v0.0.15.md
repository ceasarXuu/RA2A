# RA2A v0.0.15

## Highlights

- **Restored Codex Desktop delivery compatibility**: Codex Desktop 26.908
  raised `thread-follower-update-thread-settings` from protocol version 1 to
  version 2. RA2A now uses the current version, preventing valid, open idle
  sessions from being rejected with the misleading `no-client-found` error
  before a turn starts.
- **Regression contract updated**: Desktop IPC tests now require settings
  follower version 2, so the test double no longer validates the obsolete
  contract that masked this compatibility break.
- **Optional managed Codex CLI wrapper**: Unix and Windows installers can opt
  into a `codex` wrapper that connects plain TUI launches to the RA2A-managed
  App Server when its owner lease is healthy. Non-TUI subcommands and an
  unavailable managed host safely fall back to native Codex behavior.
- **CLI feasibility probes**: App Server probes can negotiate the experimental
  API, exercise queued delivery, and inspect account rate-limit snapshots.
  These are validation tools; the full Codex CLI adapter and cross-agent
  support matrix remain under development.

## Verification

- `go test ./internal/desktopipc ./cmd/ra2a` passes with Go 1.24.
- The installed Desktop protocol table was checked against Codex Desktop
  26.908.40834 / bundled Codex 0.154.0-alpha.6.2.
- A read-only IPC probe confirmed that the active Ubuntu session has a valid
  Desktop owner and that a method-version mismatch is surfaced by Desktop as
  `no-client-found`.
- `go test ./...` and `go vet ./...` pass in the Go 1.24 release environment.
- Windows/Ubuntu bidirectional delivery validation is still required before
  tagging the release.

## 重点更新

- **恢复 Codex Desktop 投递兼容性**：Codex Desktop 26.908 将
  `thread-follower-update-thread-settings` 从协议版本 1 升级为版本 2。
  RA2A 现已同步当前版本，避免已打开且空闲的有效 session 在创建 turn 前被
  误导性的 `no-client-found` 拒绝。
- **更新回归契约**：Desktop IPC 测试现强制要求 settings follower v2，不再由
  测试替身继续认可已过期的 v1 契约。
- **可选的受管 Codex CLI wrapper**：Unix 与 Windows 安装器可选择安装
  `codex` wrapper；当 RA2A managed App Server owner lease 健康时，普通 TUI
  会连接该受管宿主。非 TUI 子命令或受管宿主不可用时安全回退到原生 Codex。
- **CLI 可行性探针**：App Server 探针可协商 experimental API、验证排队投递并
  读取账号限额快照。这些仍是验证工具；完整 Codex CLI adapter 与跨 Agent
  支持矩阵尚在开发中。
