# RA2A v0.0.17

## Highlights

- **Automatic setup for detected harnesses:** Source and checksummed Release installers now discover Codex CLI and OpenCode, install reversible launchers, and support OpenCode-only nodes without requiring Codex. Plain interactive `opencode` attaches to the shared RA2A server; non-TUI commands still use the native CLI.
- **Cross-harness messaging contract:** `list_targets` returns complete endpoint addresses and `send_message` exposes an optional `from`, enabling explicit sender attribution when multiple OpenCode sessions are active. The Codex CLI launcher preserves a healthy official daemon and uses RA2A's managed socket only as a fallback.
- **Lifecycle and distribution:** TUI exit no longer removes the shared OpenCode server's owner record; Windows `.cmd`-launched server process trees are reclaimed. The Release includes independently checksummed RA2A, Codex wrapper, and OpenCode wrapper binaries for Linux, macOS, and Windows (amd64/arm64).

## Validation and migration

- Go 1.24 `go test -count=1 ./...`, focused race checks, `go vet ./...`, and all 18 release-target executable builds passed locally. Real Linux/amd64 release binaries were served with computed SHA256 to the unchanged Release downloader and installed successfully in an isolated HOME. A real isolated OpenCode 1.18.33 server validated the permission ask/reply path.
- The dev implementation was verified on ubuntu407, rog306, and macmini-m4. An OpenCode session on rog306 replied to ubuntu407 OpenCode with `PONG RA2A-CASUAL-20261001-CAD35785B0`.
- **Upgrade from v0.0.15:** Re-run the standard v0.0.17 Release installer once. The v0.0.15 `ra2a update` only replaces the core executable and cannot install launcher assets. Existing TUI processes must be reopened by the user to use new launchers; a running OpenCode server must restart to reload changed MCP configuration.
- Codex CLI and OpenCode are shipped as **previews** until all cross-harness/platform pairs complete real-device acceptance; Codex App remains the formally validated baseline. OpenCode invocations requesting their own server or top-level-only settings pass through the native CLI.

The v0.0.16 tag did not produce a Release: its CI test wrongly assumed that the build runner had OpenCode installed. The test now isolates PATH and verifies the intended missing-native behavior. v0.0.17 is the first Release with these launcher assets.

## 重点更新

- **自动识别宿主：** 普通安装命令自动检测 Codex CLI / OpenCode 并安装可恢复的启动器。只有 OpenCode 的设备也能完成 RA2A 初始化；普通 `opencode` TUI 自动接入共享 server。
- **互通工具契约：** `list_targets` 提供完整地址，`send_message` 的可选 `from` 解决多 OpenCode 会话的来源归因；Codex CLI 官方 daemon 可用时保持原生路径，不可用时才使用 RA2A managed fallback。
- **升级说明：** 从 v0.0.15 升级请重新运行一次 v0.0.17 正式安装器；旧版 `ra2a update` 只更新主命令，不会安装新 wrapper 资产。已运行的 TUI 须由用户主动重开；OpenCode server 的 MCP 配置更新须重启 server。
- **支持边界：** Codex CLI 与 OpenCode 标为预览，剩余全交叉设备/平台组合尚待真机验收。v0.0.16 tag 的 CI 未通过，也没有对应 GitHub Release；本次实际发布版本为 v0.0.17。
