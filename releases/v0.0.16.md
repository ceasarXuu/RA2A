# RA2A v0.0.16

> **未发布：** `v0.0.16` tag 的 Release CI 因测试假设机器预装 OpenCode 而失败，未生成 GitHub Release。该测试已改为隔离 PATH 并验证缺少原生命令时安全失败；正式发布承载版本为 `v0.0.17`。本文件保留失败版本的准备记录，不作为安装入口。

## Highlights

- **Automatic harness setup:** The source and checksummed Release installers detect available Codex CLI and OpenCode commands and install their launchers automatically. An OpenCode-only machine can set up and join the network without a Codex dependency. Reinstall and uninstall retain or restore native commands.
- **OpenCode TUI integration:** Plain interactive `opencode` attaches to the shared server, publishes only an actively attached session, and handles `--auto`/`--yolo` permission requests for that session. Non-TUI commands keep native behavior.
- **Cross-agent messaging:** `list_targets` now supplies complete endpoint addresses, and `send_message` exposes an optional `from` field so an agent with multiple OpenCode sessions can identify the sender. The Codex CLI wrapper preserves an available official shared daemon and uses RA2A's managed connection only as a fallback.
- **Shared-server lifecycle:** Closing an attached TUI does not erase server ownership; stop/exit and uninstall reclaim the shared server. Windows process-tree termination covers `.cmd`-launched servers.

## Verification

- `go test -count=1 ./...`, focused `go test -race`, and `go vet ./...` pass with Go 1.24.
- An isolated real OpenCode 1.18.33 server confirmed session creation and the permission ask/reply path; fixture tests cover OpenCode-only routing in both directions and late server startup.
- Source and Release installer fixtures cover Unix and PowerShell detection, repeat installation, checksum rejection, and native-command restoration. Cross-builds for all six supported OS/architecture targets pass.
- A local HTTP server served the **actual** Linux/amd64 Release assets with their computed SHA256; the unmodified Release installer downloaded all three binaries, installed both detected launchers, and their native `--version` pass-through plus `ra2a version` worked in an isolated HOME.
- The pre-release implementation was deployed on ubuntu407, rog306, and macmini-m4 at `08de6c4`; running daemon revisions and node readiness were verified. An OpenCode session on rog306 successfully replied to an OpenCode session on ubuntu407 using marker `RA2A-CASUAL-20261001-CAD35785B0`.

## Usage and current scope

Run the normal Release installer and then `ra2a` for first-time setup. The installer installs launchers for available harnesses without wrapper-specific flags. OpenCode sessions opened before upgrading should be reopened by the user to load the new launcher; changes to an already-running OpenCode server's MCP configuration require a server restart.

**Existing installations upgrading from v0.0.15:** Re-run the v0.0.16 Release installer once. The older `ra2a update` client only replaces the core executable and cannot install the new launcher assets; the normal installer detects and installs them without extra flags.

Codex App remains the formally validated support baseline. Codex CLI and OpenCode are provided as cross-agent previews: the Codex CLI↔OpenCode matrix and all platform combinations have not yet completed the full cross-device acceptance required for formal support. OpenCode invocations requesting their own server or top-level-only settings continue through the native CLI rather than silently changing those settings.

## 重点更新

- **自动识别宿主：** 源码与正式版安装器检测本机可用的 Codex CLI / OpenCode，自动安装并可逆地管理 wrapper。只有 OpenCode 的设备也能完成 RA2A 初始化、发现和消息收发，无需 Codex。
- **普通 OpenCode TUI 自动接入：** 交互式 `opencode` 使用共享 server；只有实际附着的会话会被发布。`--auto` / `--yolo` 仅为当前会话应答权限请求；其他子命令仍透传原生 CLI。
- **跨宿主回信契约：** `list_targets` 返回完整地址；`send_message` 正式提供可选 `from`。Codex CLI 的官方共享 daemon 可用时保持原生连接，不可用时才启用 RA2A managed fallback。
- **生命周期与校验：** 多 TUI 不再误删共享 server 的 owner；Windows `.cmd` 启动的 server 会按进程树回收。Release 包含两种 wrapper 的跨平台资产及独立 SHA256。

## 验证与边界

- Go 1.24 下全量测试、相关竞态测试和 vet 通过；真实隔离 OpenCode 1.18.33 的权限事件应答通过，六种目标平台/架构交叉构建通过。源码/Release 安装器模拟覆盖自动检测、重复安装、校验失败和卸载恢复。
- Linux/amd64 的**真实 Release 可执行资产**通过本地 HTTP/动态 SHA256 由正式下载器安装到隔离 HOME，RA2A 与两种 launcher 均能执行；Windows/macOS 的资产已完成交叉编译，但正式系统生命周期仍以真机验收为准。
- 三节点 dev 运行版本已核验；rog306 OpenCode 的 “Casual greeting” 会话成功向 ubuntu407 OpenCode 回信 `PONG RA2A-CASUAL-20261001-CAD35785B0`。
- 已运行的 OpenCode TUI 必须由用户主动重开才能加载新 wrapper；server 的 MCP 配置变更需重启 server。Codex CLI↔OpenCode 等剩余全交叉组合仍需实机验收，因此 Codex CLI 与 OpenCode 在支持列表中仍标为预览，不列为已完成正式准入。
- **从 v0.0.15 升级：** 请重新执行一次 v0.0.16 正式安装器。旧版 `ra2a update` 只替换主命令，不具备下载新 launcher 资产的能力；重新执行安装器不需要任何 wrapper 参数。
