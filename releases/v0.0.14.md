# RA2A v0.0.14

## Highlights

- **Linux orphan process-group reaping**: managed Codex hosts on Linux run as a
  two-process pair (node wrapper + codex binary). When the wrapper is killed
  (`kill -9`), the codex child previously survived as an un-reaped orphan
  holding an unlinked socket. The daemon now reaps the residual process group
  immediately when the managed leader exits — independently of the watchdog
  guard or request path — and records `event=managed_codex_host_reaped` only
  when living members were actually terminated.
- **Crash-safe cleanup ordering**: the owner lease is now cleared only after
  the residual group is reaped. If the daemon crashes in the recovery window,
  the next daemon startup reclaims the leftover process group from the
  retained lease; reap failures are surfaced as
  `event=managed_codex_host_reap_failed`.
- **Thread model from rollout**: the thread's original model is now resolved
  from the session rollout record (`session_meta.base_instructions.provenance
  .model`, falling back to the last `turn_context.model`). The app-server
  `model/list` default is no longer substituted for a thread's own model,
  eliminating an empty-model race.

## Verification

- `go test ./...` (including `-race` on codexhost) and `go vet ./...` pass.
- New unit tests cover: exit-goroutine reaping of residual process groups,
  no spurious `managed_codex_host_reaped` on normal `ra2a stop` / daemon
  Close, and daemon-crash recovery of the residual group via the owner lease.
- Live verification on Linux (node-wrapper codex): killing the managed wrapper
  logs `managed_codex_host_exited` + `managed_codex_host_reaped` with no orphan
  left behind; `ra2a stop` cleans process and lease without a misleading reap
  log.
- The release workflow builds macOS, Linux, and Windows amd64/arm64 assets
  with SHA-256 checksums.

## 重点更新

- **Linux 孤儿进程组收割**：Linux 上 managed Codex host 是双层进程（node
  wrapper + codex 二进制）。wrapper 被 `kill -9` 后，codex 子进程此前会残留为
  持有已 unlink socket 的孤儿。现在 daemon 在 managed leader 退出时立即收割残留
  进程组——不依赖 watchdog guard 或请求路径——且仅在确实终止了存活成员时记录
  `event=managed_codex_host_reaped`。
- **崩溃安全的清理时序**：owner lease 只在残留进程组收割完成后清除。若 daemon
  在恢复窗口内崩溃，下一次 daemon 启动会依据保留的 lease 回收残留进程组；收割
  失败通过 `event=managed_codex_host_reap_failed` 暴露。
- **Thread 模型取自 rollout**：thread 的原始模型改从 session rollout 记录解析
  （`session_meta.base_instructions.provenance.model`，回退到最后一个
  `turn_context.model`）。不再用 app-server 的 `model/list` 默认值替代 thread
  自身模型，消除了 empty-model race。
