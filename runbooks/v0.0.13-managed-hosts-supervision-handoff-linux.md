# v0.0.13 Linux native 交接 + 三机 hi session E2E（ubuntu407）

> 由 ubuntu407 上的 agent 执行；Windows（rog306）与 Mac（macmini-m4）侧由用户协调配合。
> 对应 runbook：`runbooks/v0.0.13-managed-hosts-supervision-handoff.md`（commit 6137d8b）。
> 本机从未做过 native 实测，本次为系统性的首次补测。

## 目标

1. **Linux native child crash smoke**：daemon 存活期间受管 Codex App Server 被 `kill -9` 后自动恢复；`ra2a stop` 后无 resurrection。
2. **三机 LAN E2E（hi session）**：ubuntu407 ↔ rog306（Windows）↔ macmini-m4（Mac）之间用各自的 "hi" session 投递唯一 marker，验证进程恢复传导到 session discovery / remote usage。
3. 每台机器 Desktop 已打开，三台机器都建了名为 "hi" 的 session。

## 固定基线

```text
release: v0.0.13
required commits: 4b7d7d9 (recover exited managed host on first probe)
                  0802c30 (supervise managed process exits)
```

- 必须使用 v0.0.13 正式 binary（`ra2a version` 输出 `v0.0.13`）。不是则先装：
  `curl -fsSL https://github.com/ceasarXuu/RA2A/releases/download/v0.0.13/install-ra2a.sh | bash`（无参安装保留现有配置）。
- 若本机有源码仓库：`git merge-base --is-ancestor 4b7d7d9 HEAD && git merge-base --is-ancestor 0802c30 HEAD`，两个都必须成功。

## 关键路径

- socket base：`$CODEX_HOME/app-server-control/app-server-control.sock`（`CODEX_HOME` 为空时是 `~/.codex/...`）。
- 每次启动派生独立 socket：`app-server-control.sock.ra2a-<daemon-pid>.sock`。
- owner lease：`app-server-control.sock.ra2a-owner.json`，内容 `{pid, socketPath, codexPath}`。
- daemon：systemd user service `ra2a.service`；日志 `journalctl --user -u ra2a`。
- 受管进程判定：`codex app-server --listen unix://...ra2a-<pid>.sock`。

## 前置收集（先跑，把输出留给报告）

```bash
set -euo pipefail
RA2A=$(command -v ra2a)
$RA2A version
systemctl --user status ra2a --no-pager | sed -n '1,4p'
DAEMON_PID=$(systemctl --user show ra2a -p MainPID --value); echo "daemon PID=$DAEMON_PID"
pgrep -af 'codex.*app-server.*\.ra2a-.*\.sock' || echo 'no managed host'
CODEX_ROOT=${CODEX_HOME:-$HOME/.codex}
OWNER=$CODEX_ROOT/app-server-control/app-server-control.sock.ra2a-owner.json
cat "$OWNER" 2>/dev/null || echo 'no owner lease'
# 本机自检：控制端点 + targets
curl -s http://127.0.0.1:47321/v1/targets | jq -r '.targets[] | "\(.id) \(.name) \(.status) sessions=\(.sessions|length)"'
```

预期：version=v0.0.13；ra2a.service active；daemon PID 与 lease 的 socket 后缀一致；targets 三台机器都在（rog306 / macmini-m4 / ubuntu407，全部 ready），且每台都有一到多个 session。

## 验证组 1：Linux native child crash smoke

1. 记录：daemon PID（记为 `DAEMON_PID`）、managed PID（记为 `MANAGED_PID`）、lease 原文。
2. **只杀 managed，不动 daemon**：

```bash
kill -9 "$MANAGED_PID"
sleep 2
pgrep -af 'codex.*app-server.*\.ra2a-.*\.sock'   # 应出现新 managed PID
systemctl --user show ra2a -p MainPID --value    # 必须仍是 DAEMON_PID
cat "$OWNER"                                     # pid 必须指向新 managed PID，socket 后缀仍是 .ra2a-<DAEMON_PID>.sock
```

断言：daemon PID 不变；旧 managed PID 消失；新 managed PID 出现；lease 指向新 PID；socket 仍是 `.ra2a-<daemon-pid>.sock`（per-launch 隔离）。

3. 退出事件日志：

```bash
journalctl --user -u ra2a --since '5 minutes ago' --no-pager | grep managed_codex_host_exited | tail -3
```

断言：出现 `event=managed_codex_host_exited pid=<MANAGED_PID>`（kill -9 应带 error 字段如 `"signal: killed"`）。

4. 恢复后 host 可用性 probe（只读，不碰 daemon lease）：

```bash
cd <仓库目录> 2>/dev/null && go run ./cmd/appserver-probe -socket "$CODEX_ROOT/app-server-control/app-server-control.sock.ra2a-$DAEMON_PID.sock" | head -20
```

若本机无仓库/Go，用 `ra2a selftest --pin $(jq -r .pin ~/.config/ra2a/config.json)`（本地读 PIN，不回传）。输出应含 `sessions=N` / `selftest=ok`，或 probe 返回 thread list。
注意：`ra2a selftest` 会短暂影响 daemon 的 managed host（CLI 与 daemon 共用 lease，属已知现象，supervision 会 1 秒内恢复），不影响结果。

5. 最后 `ra2a stop`，等待 2 秒，确认没有 supervisor resurrection：

```bash
$RA2A stop
sleep 2
pgrep -af 'codex.*app-server.*\.ra2a-.*\.sock' && echo 'RESURRECTION!' || echo 'no managed process: OK'
test ! -f "$OWNER" && echo 'lease removed: OK'
sleep 1
pgrep -af 'codex.*app-server.*\.ra2a-.*\.sock' && echo 'RESURRECTION after 1s!' || echo 'no resurrection: OK'
```

断言：managed 进程与 lease 都消失，且约 1 秒内不再出现。

6. 重新启动进入 E2E 阶段：

```bash
$RA2A restart
sleep 3
$RA2A version
```

## 验证组 2：三机 LAN E2E（hi session，协调执行）

以下步骤按顺序执行，每步完成后等待用户确认再进入下一步。marker 命名：`<方向>-<UTC时间戳>`，例如 `U2W-20260905120000`。

### 2.1 前置确认

```bash
curl -s http://127.0.0.1:47321/v1/targets | jq -r '.targets[] | "\(.id) \(.status) sessions=\(.sessions|length)"'
curl -s http://127.0.0.1:47321/v1/targets | jq -r '.targets[] | select(.id=="rog306" or .id=="macmini-m4" or .id=="ubuntu407") | "\(.id): " + ([.sessions[] | select(.title=="hi") | .id] | join(","))'
```

断言：三台 target 都在且 ready；每台都有 title=="hi" 的 session。记录三个 hi session ID。

### 2.2 Ubuntu → Windows 投递

用 ubuntu407 本机控制端点（loopback）发送唯一 marker 到 rog306/hi：

```bash
U2W=$(date -u +U2W-%Y%m%d%H%M%S)
W_HI=<rog306 的 hi session id>; U_HI=<ubuntu407 的 hi session id>
curl -s -X POST http://127.0.0.1:47321/v1/send -H 'Content-Type: application/json' \
  -d "{\"to\":\"ra2a://rog306/$W_HI\",\"text\":\"$U2W\",\"sourceSessionId\":\"$U_HI\"}"
echo "marker=$U2W"
```

断言：返回 `{"status":"accepted"}`。**协调点 1**：请用户在 rog306 的 Codex Desktop hi session 中确认 marker 恰好出现一次，然后继续。

### 2.3 Ubuntu → Mac 投递

```bash
U2M=$(date -u +U2M-%Y%m%d%H%M%S)
M_HI=<macmini-m4 的 hi session id>
curl -s -X POST http://127.0.0.1:47321/v1/send -H 'Content-Type: application/json' \
  -d "{\"to\":\"ra2a://macmini-m4/$M_HI\",\"text\":\"$U2M\",\"sourceSessionId\":\"$U_HI\"}"
echo "marker=$U2M"
```

断言：返回 `{"status":"accepted"}`。**协调点 2**：请用户在 macmini-m4 的 hi session 中确认恰好一次。

### 2.4 杀 managed + 恢复后的远端投递（核心 E2E）

1. 记录当前 managed PID（记为 `MANAGED2`），单独杀它：

```bash
MANAGED2=$(pgrep -f 'codex.*app-server.*\.ra2a-.*\.sock' | head -1)
kill -9 "$MANAGED2"
sleep 2
pgrep -af 'codex.*app-server.*\.ra2a-.*\.sock'   # 新 managed PID 出现
systemctl --user show ra2a -p MainPID --value    # daemon 不变
cat "$OWNER"                                     # lease 指向新 PID
```

2. **协调点 3**：告诉用户 "ubuntu managed 已恢复，请让 Windows 端向 ubuntu407/hi 发送 marker W2U-<时间戳>"。Windows 端发送后，确认 ubuntu407 的 hi session 收到且恰好一次。
3. 等待几秒后再次确认 targets 无 ghost、无重复：

```bash
curl -s http://127.0.0.1:47321/v1/targets | jq -r '.targets[] | "\(.id) \(.status)"'
pgrep -af 'codex.*app-server.*\.ra2a-.*\.sock' | wc -l   # 必须为 1（唯一 managed writer）
```

断言：targets 仍是三台且无重复；managed writer 只有 1 个；没有第二个 `.ra2a-<pid>.sock` 进程。

失败时附只读现场：`ra2a version`、`systemctl --user status ra2a --no-pager | sed -n '1,10p'`、进程列表、owner lease 原文、journalctl 最近 30 行；不回传 PIN。

## 不要做

- 不要 `pkill -f codex` 或 `killall codex`，不得误杀官方 Desktop App Server。
- 不要删除 rollout、session、writer lock 或 owner lease 伪造结果。
- 不要用第二个 App Server 代替 Desktop owner 投递。
- 不要以版本字符串代替 Git 祖先校验。
- 不要回传 PIN（本地读取即可，写报告时脱敏）。
- 不要重跑完整 mDNS/DTLS 回归矩阵（v0.0.13 未改 lannode）。
