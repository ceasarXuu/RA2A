# v0.0.13 managed App Server 运行时监督验证交接

## 目标

验证 v0.0.13（commit `4b7d7d9` + `0802c30`）补上的新生命周期：**daemon 存活期间，受管的 Codex App Server 中途退出后自动恢复**。

v0.0.13 补的不是「孤儿进程回收」本身。daemon 启停边界（独立 socket、owner lease、启动回收残留、关闭终止进程树、`89e2555`）此前已闭环。本发布把生命周期从「启动安全 → 关闭安全 → daemon 崩溃后可回收」推进到：

```text
                 ┌─ managed App Server 异常退出
                 │
daemon 存活 ─────┤
                 ├─ 首次请求立即发现并恢复       ← 4b7d7d9
                 │
                 └─ 没有请求也主动监控并恢复     ← 0802c30

daemon 主动关闭 ── supervise=false ── 不允许再拉起
daemon 异常死亡 ── OS service 重启 ── owner lease 回收旧 child
```

## 固定基线

```text
release: v0.0.13
required commits: 4b7d7d9 (recover exited managed host on first probe)
                  0802c30 (supervise managed process exits)
release prepare: 8c45872
repository: https://github.com/ceasarXuu/RA2A.git
```

release CI 只有 Ubuntu runner，六个平台的二进制是交叉编译，没有 Windows/macOS runner 做 native 执行。因此本次交接以 **Linux 原生 + Windows 原生 + 真实 LAN** 三组为主线，不要用交叉编译产物在非目标平台上的行为反向推断。

## 关键位置与路径

- 受管 socket base：`DefaultSocketPath()` = `$CODEX_HOME/app-server-control/app-server-control.sock`（默认 `~/.codex/...`，`CODEX_HOME` 非空时以它为准）。
- 每次启动派生独立 socket：`app-server-control.sock.ra2a-<daemon-pid>.sock`。
- owner lease：独立 socket 路径 + `.ra2a-owner.json`，内容含 `pid`、`socketPath`、`codexPath`。
- managed host 退出日志 `event=managed_codex_host_exited pid=... [status=clean | error="..."]` 写入 daemon 进程的 stderr：
  - Linux systemd：`journalctl --user -u ra2a`（daemon 作为 user service 运行）。
  - Windows Scheduled Task 默认不保留输出；若日志不可见不阻塞验收，以进程 PID/lease 变化为主判据。
- Linux 受管进程判定：`codex app-server --listen unix://...app-server-control.sock.ra2a-<pid>.sock`。
- Windows 受管进程判定：`codex.exe` 命令行含 `app-server.*\.ra2a-\d+\.sock`（官方 Desktop App Server 不含该模式，不要混淆）。
- Linux service：systemd user `ra2a.service`；Windows：Scheduled Task `RA2A`。

## 验证组 1：Linux native child crash smoke

使用 v0.0.13 release binary 或本次源码安装（以 Git 祖先校验为准）：

```sh
git merge-base --is-ancestor 4b7d7d9 HEAD || exit 1
go test ./... && go vet ./...
```

无真实 Codex 的云机上可用最小 fake App Server fixture 模拟 `app-server --listen`（仅验证 Linux OS 生命周期，不算 Codex interoperability PASS）；有真实 Codex 时直接用真实 `codex app-server`。

步骤：

1. 记录 daemon PID、managed PID、owner lease/socket。
2. **只杀 managed 进程，不动 daemon**。
3. 不主动调用 RA2A，等待约 1 秒（restartDelay）到数秒，观察是否出现**新 managed PID**。
4. 执行一次 `ra2a selftest`（输出 `sessions=N` / `selftest=ok`），确认新 host 真正可用。
5. 最后 `ra2a stop`，等待数秒，确认**没有 supervisor resurrection**。

断言：

- daemon PID 不变；旧 managed PID 消失；新 managed PID 出现。
- owner lease 指向新 managed PID，socket 仍是 `.ra2a-<daemon-pid>.sock`（per-launch 隔离）。
- `journalctl --user -u ra2a` 出现 `event=managed_codex_host_exited`（错误退出含 error 字段）。
- `ra2a stop` 后 managed 进程与 lease 消失，且约 1 秒内**不再出现**。

## 验证组 2：Windows native（P0）

这是当前最大验证缺口。Windows 进程树回收语义与 Unix 不等价（Unix `kill(-PGID, SIGKILL)` vs Windows `taskkill /PID <pid> /T /F`），本组的 child 中途退出与 stop/supervisor 竞态此前**从未 native 验证过**。

必须使用 v0.0.13 正式 `.exe`。前置收集命令：

```powershell
$UserHome = [Environment]::GetFolderPath('UserProfile')
$CodexRoot = if ($env:CODEX_HOME) { $env:CODEX_HOME } else { Join-Path $UserHome '.codex' }
$ControlDir = Join-Path $CodexRoot 'app-server-control'
$OwnerPath = Join-Path $ControlDir 'app-server-control.sock.ra2a-owner.json'
Get-ScheduledTask -TaskName RA2A | Select-Object TaskName, State
Get-CimInstance Win32_Process -Filter "Name='ra2a.exe'" |
  Select-Object ProcessId, ParentProcessId, CommandLine
Get-CimInstance Win32_Process -Filter "Name='codex.exe'" |
  Where-Object { $_.CommandLine -match 'app-server.*\.ra2a-\d+\.sock' } |
  Select-Object ProcessId, ParentProcessId, CommandLine
if (Test-Path -LiteralPath $OwnerPath) { Get-Content -LiteralPath $OwnerPath -Raw }
```

### 2.1 child-only kill（本发布核心路径）

```powershell
$BeforeManaged = Get-CimInstance Win32_Process -Filter "Name='codex.exe'" |
  Where-Object { $_.CommandLine -match 'app-server.*\.ra2a-\d+\.sock' } |
  Select-Object -First 1
Stop-Process -Id $BeforeManaged.ProcessId -Force
Start-Sleep -Seconds 5
$Daemon = Get-CimInstance Win32_Process -Filter "Name='ra2a.exe'" |
  Where-Object { $_.CommandLine -match "\sdaemon(\s|$)|ScheduledTask" } |
  Select-Object -First 1
```

断言：

- daemon/Scheduled Task PID **不变**；旧 managed PID 消失；出现**新 managed PID**（同 `.ra2a-<daemon-pid>.sock`）。
- owner lease `pid` 指向新 managed PID。
- 执行一次 probe/`ra2a selftest`，确认新 host 可用。

### 2.2 stop 无 resurrection

```powershell
& $Ra2a stop
Start-Sleep -Seconds 5
$AfterManaged = Get-CimInstance Win32_Process -Filter "Name='codex.exe'" |
  Where-Object { $_.CommandLine -match 'app-server.*\.ra2a-\d+\.sock' }
if ($AfterManaged) { throw 'RA2A managed App Server resurrected after stop' }
if (Test-Path -LiteralPath $OwnerPath) { throw 'owner lease survived stop' }
```

### 2.3 daemon 强杀 + 计划任务自愈回收

**仅当** `runbooks/windows-managed-app-server-lifecycle-handoff.md`（基线 `89e2555`）没有保留实际 PASS 证据时执行；有 PASS 记录则可跳过。

```powershell
$CrashDaemon = [int]$Daemon.ProcessId
$CrashManaged = [int]$Managed.ProcessId
Stop-Process -Id $CrashDaemon -Force
# 等待 Scheduled Task 拉起新 daemon（90 秒窗口），随后检查：
# 新 daemon PID 出现且 != CrashDaemon；
# 旧 managed PID 已被回收（Get-Process -Id $CrashManaged 不存在）；
# 新 managed PID 与新 lease 一致。
```

不要 `taskkill /IM codex.exe` 或 `Stop-Process -Name codex`，会误伤官方 Desktop。

## 验证组 3：真实 LAN（Mac ↔ Windows）单条 E2E

只跑一条跨层验收，证明底层 process recovery 传导到用户真正依赖的 session discovery / remote usage：

1. Desktop 正常，Mac 能看到 Windows target。
2. 记录 Windows managed PID，单独杀掉它（不动 daemon）。
3. 等待 supervisor 自动恢复。
4. Mac **不重启 RA2A**，重新取得/使用同一个 session，发送一个新的唯一 marker。

断言：

- session 可恢复；
- 消息只出现一次（唯一 marker 成功一次）；
- 没有 ghost target；
- 没有额外 managed writer（不出现第二个 `.ra2a-<pid>.sock` 进程）。

## 不需要重跑

v0.0.13 未改 `lannode`，不要重跑完整 mDNS/DTLS 生命周期矩阵（30 秒 TTL、goodbye、同 IP/端点恢复、改端口恢复、DTLS pre-delivery retry）。这些属独立 LAN contract，仓库已有既有规则与 Windows 双机 handoff。

## 已知残余风险（代码级，非本发布阻断）

`watchProcess()` 的自动重启调用 `_ = host.ensureConnected(ctx)` 会丢弃错误。若第一次自动 restart 的 `command.Start()` 恰好失败（文件锁、瞬态资源错误），没有新 process 也就没有新 watcher，系统会退回「等下一次业务请求再次触发 `ensureConnected`」的请求驱动恢复。

当前实现严格说是「**正常可重新启动条件下的自动自愈**」，还不是「持续 bounded backoff 直到恢复」。这不阻塞 v0.0.13，已知即可；若后续出现「Codex 刚升级 / 文件锁导致一次 launch 失败」的诉求，这是下一个自然生命周期缺口。
