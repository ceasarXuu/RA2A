## Requester Review Summary

- 单机运行多个 RA2A 节点与真实客户端，验收端侧适配；跨设备验收重点保留真实网络差异。
- 复用设备已有 Auth / API key，避免每轮重新认证；使用真实模型会消耗设备账户额度。
- 默认每个 Agent 接收额度 10 条，超过必须明确解释原因，不继续触发该接收端模型。
- 待确认：额度统计采用本轮同类 Agent 的总量还是每个原生会话分别计数；是否采用保守预留不退回；凭据刷新是否允许写回正式认证。
- 建议方案与已确认决策分开，Draft 不授权生产实现或正式 App 接入。

## 1. 目标和验收边界

沙盒提供一次可重复运行的环境：启动独立节点、打开客户端、运行有界矩阵、展示原生证据、最后由用户核对窗口及手工继续输入。正式设备配置、会话、服务和进程不得被沙盒接管。

覆盖 Codex CLI、Codex App、OpenCode、Pi 四类 Agent。完整覆盖要求真实二进制、真实 TUI / App、真实 RA2A 适配与投递链；SDK、fake App、mock provider 的通过结果单独列出，不能替代完整覆盖。

Linux 是首个平台；Windows/macOS 后续复用矩阵定义与报告字段，隔离启动方式逐平台实现。单机虚拟网络不证明宿主物理网卡、防火墙或真实跨设备路由。

## 2. 用户流程

1. 预检查显示源码版本、客户端版本、可用认证类型、隔离能力和计划消耗，认证检查本身不调用模型。
2. 生成本轮私有目录和节点身份，仅将所需认证导入私有客户端环境。
3. 显示运行计划及每类 Agent 接收预算；启动真实客户端与私有 RA2A 节点。
4. 顺序执行自动项目；报告分别展示收件、执行完成、错误、重复、unknown 和未执行项。
5. 自动阶段完成后给出人工操作清单，用户核对真实窗口和继续输入。
6. 结束或失败时仅停止本轮拥有的进程，处理凭据副本，保留脱敏报告；未能证明资源归属时保留并报告，不按进程名批量清理。

## 3. 凭据与配置

- 优先复用现有 provider/model 与 Auth/API key，不读取或打印无关凭据。
- 提议：文件认证复制到权限受限的本轮私有目录，允许客户端刷新副本；正式认证不挂载为可写。API key 环境变量只传给需要它的进程，不进入命令行和报告。
- 系统钥匙串、Secret Service 或设备绑定认证能否隔离复用尚需验证；不可用时明确报告认证不支持，不能悄悄改正式认证方式或让模型失败冒充协议失败。
- 不复制正式会话、工作区、插件全集或 MCP 服务全集。只生成验收工作区、必要 provider 配置、RA2A MCP/extension 和测试指令。
- 同一认证的刷新可能使其他 token 失效，复制文件不等于账户层面无副作用；该风险须在预验证中确认。

## 4. 额度规则：已确认与待确认

已确认默认 10 条并在超过时解释原因。以下精确定义是建议，尚不作为用户权威：

| 项目 | 建议语义 |
|---|---|
| 统计桶 | `(run_id, agent_kind)`；该类 Agent 所有接收会话、发送方、重启与 resume 共用 10 条，不能新建会话绕过 |
| 计数边界 | 进入原生客户端前预留一条，初始化模型输入、忙时追加、自动回信及人工测试输入均受约束；发现、查询、传输 ACK 不计 |
| 错误与 unknown | 一旦预留就不退回；明确未写出的失败也占本轮预留，保守限制调用规模；报告同时列预留和实际收件数 |
| 重复请求 | message-id 只关联已记录结果，不再次写入，不重新分配额度；unknown 不自动重发 |
| 并发与重启 | 计数在可信控制端持久化并原子预留；状态不明或控制端失联时停止付费输入，不重置计数 |
| 超额 | 第 11 条起在原生输入之前拒绝，暂停依赖该接收端的项目，说明原因及尚未执行项目 |
| 调整 | 提高默认额度须用户明确指定；本轮不自动开启下一轮来续费 |

示例提示：`Pi 本轮接收预算已用完：10/10；下一条已拦截，未送入模型。为限制真实额度消耗，busy-followup-02 尚未执行。`

10 条消息不是 10 次底层模型请求或金额上限：工具循环、重试、长上下文仍可能多次计费。提议关闭验收无关的自动任务/重试，串行调度、限制案例时长并停止异常循环；不能把消息计数报告为消费金额保证。

## 5. 验收要求

- 所有发布地址只属于本轮私有节点；正式 RA2A 的节点、PIN、配置和会话不参与。
- 每一成功项都有接收端原始 message-id、原生输入记录与精确最终 marker；accepted 单独列示，不替代模型完成或屏幕显示。
- 同一 run 关闭客户端、服务重启、恢复会话后，预算不重置；并发冲击不能超发；预算用尽原生 user message 与模型请求均不新增。
- 活跃收件 ACK 不等待模型工作结束；业务回复另行核验。未知是否写入不自动重放。
- Codex 同一原生 ID 的 CLI→App→CLI→睡眠验收采用真实锁与真实客户端；当前所有权根治尚未集成时，相关项目必须标 BLOCKED，不能让模拟桥通过掩盖缺口。
- 人工步骤放在自动验收最后，并明确剩余预算；没有屏幕观察证据的 UI 项标 MANUAL_PENDING。
- 失败、取消、超额、认证失效或隔离不足都报告未执行项目，不整体标 PASS。

## 6. Open Questions And Risks

1. 第4节统计桶、预留不退回和计入初始化/回信/人工输入是否采用？先前助手解释不等同用户直接确认。
2. 建议正式认证只读导入、副本内刷新且不自动写回；设备绑定凭据的兼容与刷新失效风险待验证。
3. 默认 10 条不足以覆盖所有故障变体；需明确本轮排程与未执行项，不能自动多轮消费。
4. Linux GUI / IPC / D-Bus 隔离与认证必须先验证；环境变量改路径不足以证明隔离成功。
