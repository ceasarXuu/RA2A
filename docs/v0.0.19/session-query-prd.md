# PRD：当前会话地址与本机 PIN 查询

- 状态：Ready for implementation；工程接口与分阶段预算尚需制定，不代表已实现。
- 创建 / 更新：2026-10-08。
- 发布目标：v0.0.19。
- 请求：Owner「加入 0.0.19 的目标中，提供这两个功能」。
- 背景：现有 MCP 仅 list_targets/send_message，没有当前会话身份或 PIN 查询入口；ra2a pin 是修改操作，不能作为查询使用。

## 目标与范围

让使用 RA2A 的 Agent / 用户直接取得当前会话投递地址，并按需只读取得本机节点的既有 PIN，不再依靠枚举列表匹配、手工拼接地址或读取配置文件。

- 提供当前 session 地址查询工具，并区分身份能否确定和端点当前是否发布、是否可投递；地址已知不等于投递可用。
- 提供本机现有 PIN 的只读查询工具。PIN 属于 RA2A 节点，不是每个 session 的独立 PIN。
- 查询覆盖已接入宿主的当前会话上下文；切换、恢复会话后应指向当前原生会话，历史会话不代表执行权。
- 查询本身不修改配置 / PIN / 登录 / 模型 / 代理，不启动、接管或重启宿主和 RA2A 服务。
- PIN 仅在调用者明确查询时返回，不追加到普通发现、地址结果、消息 envelope 或远端发现广播，不查询其他设备的 PIN。

## 用户流程与验收条件

1. Agent 在当前会话调用地址查询，直接得到完整不透明地址及当前发布 / 可用状态；无需自行拼接内部结构。
2. 若无法确认当前身份，明确返回无法确定及原因；不借用同名历史会话或其他活跃实例的地址。
3. 多实例 / 切换 / resume 后，再次查询正确绑定当前会话；未发布端点如实标记，不能报为可投递。
4. 调用本机 PIN 查询，返回既有配置 PIN；没有配置或读取失败时明确错误，不生成、重置或覆盖值。
5. 两项查询前后配置内容、正式服务状态、宿主任务保持不变；常规日志不记录 PIN 明文。
6. 文档明确区分查询 PIN 与既有 ra2a pin 修改命令，避免用户误操作。

## 工程待制定项与边界

- 工具命名、两入口是否拆分、CLI 同步入口及结构化字段在工程方案中落实；不能据此扩张为远端凭据查询或自动修复 / 注册功能。
- 各宿主的调用上下文绑定能力需基于实际接口核验；没有上下文时失败行为仍必须明确，不猜测身份。
- 使用现有本地控制与配置访问边界；PIN 必须按需显式查询，不进入常规发现输出或日志。若方案需要改变权限 / 可见性边界，应先确认。
